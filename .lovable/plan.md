# طلبات تقرير PVsyst ومخطط SLD

## الفكرة
البوت لا ينشئ التقرير مباشرة. العميل يطلبه، فيصل الطلب للتطبيق، والموظف يراجعه ويرسله.

```text
العميل يطلب PVsyst أو SLD من البوت
  -> البوت يرد: "تم استلام طلبك، سيصلك قريباً"
  -> الطلب يظهر في التطبيق (اسم العميل، رقمه، منظومته، نوع التقرير)
  -> الموظف: [فتح التقرير] للتأكد  ثم  [إرسال للعميل] على واتساب
```

## ما سيُبنى
1. **ملفات التقارير لكل منظومة**: في العروض الجاهزة، لكل منظومة خانتان لرفع ملف PDF: تقرير PVsyst ومخطط SLD. تُرفع مرة واحدة.
2. **صفحة «طلبات التقارير»** في التطبيق، بتبويبات: جديدة / مُرسلة.
   - كل طلب يعرض العميل والمنظومة ونوع التقرير.
   - زر «فتح التقرير» يفتح الملف المرفوع لمنظومته.
   - زر «إرسال للعميل» يرسل الملف على واتساب ويحوّل الطلب إلى «مُرسلة».
   - إذا لا يوجد ملف مرفوع لتلك المنظومة يظهر تنبيه «ارفع الملف أولاً».
3. **ربط البوت**: عند طلب PVsyst/SLD يرسل البوت الطلب للتطبيق ويرد على العميل برسالة استلام، بدل إنشاء التقرير فوراً.

عرض السعر لا يتغير.

## تفاصيل فنية
- جدول `report_requests` (phone, customer_id, name, preset_id, system_label, kind pvsyst|sld, status pending|sent, sent_at, created_at) مع RLS وGRANT لـ service_role فقط، مثل باقي الجداول.
- جدول `preset_reports` (preset_id, kind, file_url) + حاوية تخزين للملفات.
- نقطة `/api/public/bot-report-request` محمية بـ `x-bot-secret` مثل `bot-order`.
- الإرسال عبر مسار `sendAttachment` الحالي (webhook n8n `actes-send`).
- في n8n: استبدال فرع "Send Study PDF" بطلب HTTP للنقطة الجديدة + رسالة استلام، مع تمرير المنظومة المختارة.
- اختبار: طلب بدون ملف مرفوع لا يُرسل؛ الطلب المُرسل لا يُرسل مرة ثانية.
